# AEROCK v2 — 공연 중심 밴드 운영

기존 GitHub Pages 앱을 대체할 검정·그레이·오렌지 리디자인입니다. `?demo=1`은 샘플 데이터로 작동하며 Supabase 인증·쓰기 API를 호출하지 않습니다.

## 포함 기능
- 홈: 공연 D-Day, 내 다음 합주, 내 참여곡, 모집 마감.
- 회장단: 공연 생성·수정, 포스터 이미지 등록/삭제, 모집 마감 설정, 담당 합주부장 배정, 최종 선정 결과 등록, 회원 승인.
- 공연곡: 세부 파트별 신청, 담당 부장 확정/해제/참여자 추가, 추가 모집, 준비 사항 관리.
- 프리폼: 빈 파트에 직접 참여·취소, 목적 비고, 회장단만 곡 숨김 삭제. 기존 참여 구성을 공연 신청으로 복사.
- 시간표: 06~24시 30분 단위 드래그/터치, 가능·불가·미정, 날짜별 입력, 모든 곡에서 재사용.
- 합주: 공통 시간 추천·겹침표, 기존 합주 충돌 차단, 여러 곡/방/시간 구간, 일정 확인·조율 요청과 변경 후 재확인.
- 카카오 로그인 및 기존 임원 계정 로그인. 악기·조 입력 없음. 기존 leader1~3 역할을 합주부장으로 표시.
- 곡 책임자·투표·정산·카카오톡 링크 기능 없음.

## 데이터와 운영 반영

회원 정보는 기존 `member_profiles`를 사용합니다. v1의 `aerock_records`, `aerock_practices`는 삭제하거나 변경하지 않습니다. 새 곡·시간표·합주는 `aerock_v2`에서 빈 상태로 시작합니다.

운영 Supabase에 `schema.sql`을 적용했고 GitHub Pages에 배포했습니다. 새 시간표 UI는 날짜별 데이터만 사용합니다. 이전 `maybe` 값은 읽을 때 미정으로 정규화하고, 주간 `w0`~`w6` 값은 반복 적용하지 않습니다. 새 저장은 날짜별 값만 보내며 편집 중에는 서버에 쓰지 않습니다.

포스터는 업로드 시 최대 1200px WebP로 압축하여 공연 레코드에 저장합니다. 각 이미지는 약 750KB 이하로 제한됩니다. 소규모 동아리를 위한 초기 구현이며 향후 이미지 수가 늘면 Storage로 분리할 수 있습니다.

## 검증

- `node --test core.test.cjs schedule.test.cjs` — 3개 상태, 날짜별 입력, 기존 조율 가능의 미정 처리, 연속 가능 시간, 예약 충돌, 자정 경계, 복수 파트 인원 중복 제거.
- `npm install --no-save @electric-sql/pglite@0.3.14` 후 `node db.test.cjs` — 격리된 PostgreSQL에서 schema·역할 권한·직접 쓰기 차단·신청/확정/취소·경합 revision·중복 예약·확인 revision 검사. 실제 Supabase publication 문장만 로컬 테스트에서 제외.
- 브라우저 샘플 테스트: 프리폼 참여, 조율 요청, 시간표 저장, 여러 곡 추천/예약, 모바일 390px iframe 반응형 레이아웃.
- 실제 카카오 신규 가입, 운영 Supabase API 연결, 실시간 다중 브라우저 동기화는 운영 반영 후 테스트 계정으로 검증해야 합니다.
